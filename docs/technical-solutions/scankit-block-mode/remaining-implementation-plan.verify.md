## 1. 验证前置条件

当前真实未完成项暂无。剩余内容均已完成实现并通过任务级验证；REM-001～REM-040 不再作为重复编号。

P1-T05 已完成：能力注册表快照、注册表顺序校验及默认矩阵；高级能力按 AVX512/VBMI、AVX2、SSE4、SSE、SVE2、SVE、NEON 逐级选择，未知架构和能力不足时回退通用实现。

P5-T01 已完成复核：Castle 的预算路径与普通路径统一执行复杂分支的反向接受确认，确保循环/分支在限量执行时不产生未确认结束位置；布局损坏、队列和长度超限继续安全回退，并通过复杂分支循环一致性验证。

P5-T02 已完成复核：LimEx 使用独立位集合状态与调用级工作区；复杂分支、可空路径和重复控制节点在预展开闭包中推进。热循环同时按源掩码和紧凑源状态列表裁剪，异常、epsilon 和死状态不会进入消费路径；布局内存、步骤和结果预算均有统一出口。

P5-T03 已完成复核：Sheng 稠密表路径在进入 256 路转移前使用按字节源计数及活动位图交集裁剪；McSheng 稀疏布局增加源计数校验、复杂闭包内存门禁和同一预算出口。两种执行策略均共享闭包、死状态和结果去重语义，损坏布局可预测地回退。

P5-T04 已完成复核：Tamarama 使用连续范围合并、字节桶索引和预展开闭包，运行时先通过字符掩码裁剪不可消费状态；Vermicelli 在稀疏布局上维护确定性前缀候选状态并在候选失败时安全返回。两者均纳入闭包内存门禁、长度/步骤/结果预算和布局校验，复杂或损坏图回退通用确认。

P5-T05 已完成复核：Shufti/Truffle 共享独立半字节状态布局，支持高/低半字节两种掩码模式；热循环按活动位图、半字节掩码和源状态交集推进，并覆盖尾部、空输入及损坏布局校验。闭包、源掩码和转移内存纳入预算，异常图安全回退标量确认。

P5-T07 已完成复核：LBR 编译器仅接收可证明的边界断言和字节消费图，建立独立后继表、字符类掩码、死状态和前缀候选；运行时统一处理断言、消费、接受、结果去重、队列上限、步骤上限和结果上限。队列字节预算纳入布局校验，确认失败继续回退通用路径，NG 不可转换结构不会误入 LBR。

P5-T11 已完成复核：统一资源门禁覆盖状态、边、内存、步骤和结果；各引擎布局校验均检查索引、闭包、掩码、死状态和起始元数据，损坏布局会回退通用确认。现有跨引擎 conformance corpus 覆盖空匹配、重叠、边界、Unicode、重复、区间、序列化、预算和非法图场景。

P6-T02 已完成复核：Fuzzy 原子路径现支持文字、字符类、通配、有限分支和有限重复；Hamming 与 Edit 路径均在最终结果前执行原子确认，并保留大小写、DotAll、宽度变化和多结束位置语义。UTF-8/UCP、空分支及不可证明结构继续回退完整 AST，避免候选误报或漏报。

P8-T04 已完成复核：Miracle 支持多角色共享首字节候选桶，候选命中后统一执行角色边界、锚定、末尾和偏移约束；结果按偏移/角色稳定排序并去重，区间与限量入口复用同一候选确认逻辑。无法使用 Miracle 的角色继续由共享匹配器或完整角色扫描确认。

## 5. 证据记录规则

- 每个任务完成后记录代码路径、命令和关键断言，不记录无关的重复命令。
- 测试失败必须记录原因、修复和重新验证结果。
- benchmark 只比较同一环境的历史数据，不跨平台宣称绝对性能达标。
- 未执行或仅有基础实现的任务不得标记为“已完成”。
